# Known issues and limitations

- The locked Composer dependency audit is configured in both API CI jobs. A local audit found no advisories; hosted CI confirmation is pending.
- API liveness (`/api/v1/health`) and database readiness (`/api/v1/health/ready`) are separate. The Render blueprint now uses database readiness, which does not probe queues, object storage, mail, AI, payments, or conferencing. The free-plan blueprint does not automate schema migrations; deployment operators must follow `docs/DEPLOYMENT.md` before releases with pending migrations.
- CI now runs a fresh migration, rollback, and re-application smoke on disposable SQLite and PostgreSQL databases. The SQLite sequence passed locally; the PostgreSQL job remains pending hosted CI execution.
- Task edit, completion, archive, and restore now lock the workspace-scoped task inside a transaction; sequential API behavior passes locally, but SQLite cannot verify the concurrent row-lock behavior and the PostgreSQL CI run remains pending.
- Support-feedback response/status updates now lock the workspace-scoped feedback row and commit submitter notification changes atomically; sequential workflows pass, while concurrent row-lock behavior still requires PostgreSQL CI verification.
- Assessment answer saves and submissions now serialize on the same tenant-scoped attempt row; post-submit answer edits are rejected and the answer/score regression passes. SQLite cannot verify concurrent locking; PostgreSQL CI remains pending.
- `docs/openapi.json` is generated from registered API routes and checked by `php artisan openapi:export --check`. All registered request bodies have route-specific contracts instead of generic `JsonObject`, and no registered JSON success response currently references the generic `ApiResponse`; route tests guard both conditions. Request and success response fields are detailed across authentication, organizations/memberships/invitations, catalogs/checkout, workspace data, AI, announcements/tasks, subscriptions/platform administration, assessments/imports, payments, and assignments. Controller-to-schema audits have constrained learner result review statuses and correctness-data omission; confirmed learner/workspace dashboard nullability and empty-profile behavior; guardian summary capability omissions, nullable values, and empty-data behavior; assignment/submission permissions, grading nullability, and attachment fields; invoice visibility, payment fields, aggregate metrics, and pagination; and assessment attempt/review nullability and answer-key projections. Focused regressions check tenant IDs, whole-class and section-specific teacher assignment for assessment results, review, analytics, grade exports, section-scoped rubric grading, course-assignment grading, and current-role announcement notification visibility; rubric and CSV import response fields are also covered. Multiple-class combinations and other route families still need detailed response-field and authorization review. Lifecycle actions with no input omit request bodies; field-level validation, business behavior, and tenant authorization remain documented in `docs/API_SPECIFICATION.md`.
- Learner assignment responses and educator grading fields have learner-specific accessible names; workspace navigation exposes the current page to assistive technology. Representative public/auth text meets WCAG AA contrast. Axe-core Playwright scans cover public home, sign-in, owner dashboard, manager announcements, educator AI tutor/teaching-draft forms and results, platform-admin usage/history, learner dashboard, educator attendance, guardian learning and billing, and assessment authoring/review at desktop/mobile widths and currently pass (11 scenarios, 26 surface scans). Other role-specific modules, dialogs, and interaction states are not all scanned; manual screen-reader, keyboard-only, cross-browser, and device-level checks remain pending.

- Local email verification is disabled in Laravel configuration, and unverified users can sign in when `auth.require_verified_email=false`. The local sign-in screen displays no verification controls at port 5174; the API returned 200 on port 8013. If the UI reports verification is required after a config change, clear Laravel's config cache and restart the API. The resend screen is intentionally shown only when `VITE_REQUIRE_EMAIL_VERIFICATION=true`. Local SQLite cache and session stores use files to avoid avoidable database contention.

- Browser CSV exports share formula-safe cell encoding, including values preceded by whitespace. The backend grade export uses equivalent escaping. Authentication, marketplace, role settings, question import, assessment results/analytics, and the authenticated workspace module are loaded on demand; the latest production build's main JavaScript chunk is 333.37 kB (94.04 kB gzip), with the workspace in a separate 254.10 kB chunk (53.23 kB gzip). The PWA precaches the deferred chunk for offline availability.
- Public course and plan catalogs are read-only and rate-limited. Checkout remains sandbox-only; signed payment webhooks are rate-limited and do not move funds. Authenticated organization APIs require an active account and require verified email when PAATHNEXUS_REQUIRE_EMAIL_VERIFICATION is enabled; this defaults off only for APP_ENV=local.
- Local development uses Laravel's log mailer, so `api/.env` sets `PAATHNEXUS_REQUIRE_EMAIL_VERIFICATION=false`; Laravel must be restarted after changing this setting. The current API process is running with verification disabled, and the auth screen hides the verification step unless `VITE_REQUIRE_EMAIL_VERIFICATION=true` is explicitly set. Production email-provider delivery remains to be configured. The persistent SQLite database now contains four synthetic demo accounts across two workspaces; it does not contain the user's earlier account or credentials.
- Never point PHPUnit at the persistent app database. The suite uses isolated in-memory SQLite; the accidental earlier reset was followed by the authorized local-only demo seed. Do not treat these synthetic accounts as recovered user data.
- The local sign-in browser regression confirms the verification prompt and resend link stay hidden. An unverified synthetic demo account was also signed in successfully through the live API with the temporary token revoked afterward.
- Platform usage history stores counts only and begins accumulating after `platform:capture-usage-snapshot` first runs on the UTC scheduler, so it has no historical backfill. A Chromium regression checks the accessible daily chart labels and newest-first exact-value table.
- Playwright passes all 49 Chromium tests, including axe scans, when run on an isolated local port with loopback access enabled. The production-preview offline PWA test passes. Physical mobile/assistive-technology checks and additional browser engines remain pending.
- Workspace counts, class roster, attendance trend, tasks, attendance records, and today's timetable are API-backed.
- Staff task management has a dedicated Open/Completed/All/Archived view with completion, create, edit, optional date-only due dates, assignment to active workspace staff, and recoverable archive/restore actions. Permanent deletion is not implemented. Date-only task deadlines retain their calendar date; the workspace header and timed academic deadlines use the configured workspace timezone.
- Weekly timetable entries can be edited with class/teacher collision checks. Workspace managers can create date-specific closures, class/section cancellations, and extra lessons; only one active closure is allowed per date and cancellation is recorded as a retained status change. The UI does not edit exception details or select an individual weekly lesson to cancel. Class teacher assignments can be changed or ended with history; subject offerings can be offered or ended. Teacher profiles can optionally link to one active teacher member in the same workspace.
- Courses, lessons, enrollment, learner progress, and assignment workflows are implemented. Staff can edit courses/lessons, keep courses in draft, and archive/restore lessons while preserving learning history; hard deletion is not supported. Student profiles must be linked to an active student membership before that learner can use the student course view.
- Student memberships open to a learner dashboard showing enrolled course completion, upcoming assignments, recent quiz results, upcoming classes, a persisted personal study planner, and attendance rate/recent records. Rules-based study suggestions prioritize upcoming unsent assignments, recently reviewed assessment scores below 70% when results permission allows, and courses with remaining lessons. They are not AI-generated; adaptive recommendations and a broader pedagogical review remain future work.
- Guardians with `courses.view` see the linked learner's eight nearest published assignments from active course enrollments and their due/submission status. Submission content, attachments, and marks are not exposed; overdue assignments are excluded from this upcoming-work list.
- Academic reports show attendance, learning, assignment, and assessment summaries. Workspace managers can filter by active class, learner, and date range and export the filtered report as CSV; teachers receive assigned-class data only. Published assignment workload counts use each student's active enrollments in active courses, while date ranges filter submissions and other dated activity; course completion and assigned-work totals remain current-state. Teacher academic, attendance, timetable, dashboard, report, and course learner data use active whole-class or section assignments in the current year. Assessment reports include score bands, monthly averages, per-assessment and per-course summaries. Workspace fee balances remain all-time; a separate collections report filters recorded payments by received date. Cohort comparisons remain undefined. Reports can print or use the browser dialog to save as PDF, but the application does not directly generate or download academic-report PDFs.
- Public homepage plus direct `/features`, `/educators`, `/courses`, and `/pricing` routes, responsive mobile navigation, live plan/course catalogs, and course details are implemented. Educator profiles are visible only when opted in and attached to a public course; a standalone searchable instructor directory remains unimplemented. Signed-in linked student accounts can self-enroll in free public courses and open the owning workspace. Managers can list courses with an INR price in paise; paid courses require a sandbox order and signed capture before the API grants enrollment. The order/webhook contract is sandbox-only; an actual provider checkout UI/integration, educator payouts, and course imagery remain unimplemented. Courses stay private unless managers opt in.
- New workspace registration currently opens the workspace overview immediately; a resumable guided onboarding checklist for workspace settings, academic setup, classes, and invitations remains unimplemented.
- English/Hindi locale selection is persisted per browser and translates the public website, account-entry screens, and signed-in workspace shell (role-based navigation, search, notifications, profile controls), learner dashboard and study planner, educator task management and class roster/attendance, academic-year and timetable controls, dated schedule changes, educator AI tutor and teaching-draft controls/privacy guidance, live classroom and session-attendance controls, workspace invitation forms/link-sharing/statuses, guardian family summaries (attendance, learning, results, upcoming exams, homework, and CSV headers), fee invoices/collections (including statuses, dates, receipt content, and collection CSV headers), owner plan/subscription billing, platform plan authoring/editing and verified request review, platform usage/history, organization management, audit summaries, known feature flags, workspace announcements, educator academic reports (filters, metrics, score-band/trend tables, and CSV headers), member/manager feedback workflows (form, categories, statuses, response controls, counts, and dates), and Help Centre FAQs/search/contact actions. Guardian-link controls and most other workspace content, most API validation messages, arbitrary entitlement labels, authored organization/class/teacher names, technical audit event keys, and educator-authored/generated content remain in their original language; authored content is not automatically translated. AI output language still depends on the requested output language and provider behavior. Schedule exception editing and cancellation of individual weekly lessons are not implemented.
- The public site exposes banner, main, and contentinfo landmarks and a keyboard skip link. The mobile menu is keyboard-operable, closes with Escape, and returns focus to its toggle after menu navigation. Course details keep Tab and Shift+Tab focus within the open dialog, close with Escape, and restore focus to the course card trigger. Chromium Playwright smoke tests check the homepage at 320, 375, 430, 768, 1024, and 1440 pixels and cover menu focus and auth entry. - PWA manifest, icon, and production app-shell service worker are present. Chromium verifies that the cached shell and lazy-loaded entry screens survive an offline reload; authenticated API data remains unavailable offline. Browser install prompts and physical-device behavior have not been validated.
- Guardian links and per-student attendance, lesson-progress, and quiz-result summaries are available, including scoped CSV downloads. Workspace invitations support teacher/student/guardian roles, one-time acceptance, and revocation. Accepted invitations now direct managers to the Schedule, Courses, or Guardian links profile-linking workflow; linking remains an explicit manager action, and invitation email delivery is not configured. Broader downloadable reports remain unimplemented.
- Assignments support text or up to five private file attachments per submission; educators can attach resources, and scoped users download files through authenticated routes. The default disk is private local storage and needs a persistent private disk configuration in production. Assignments support manual grading. Quizzes support single-choice, multiple-select, and human-graded short answers, topic/difficulty, per-question points, configurable attempts, exact-match objective scoring, stable random sampling/order, CSV import for objective questions, question accuracy reports, manager review, partial credit, reusable weighted short-answer rubrics, filtered grade CSV exports, and feedback to learners. - The Students page provides a searchable active roster and manager-only student creation; class enrollment remains in My classes. Reports and attendance shortcuts are now hidden unless the workspace role includes the view's required capabilities. The learner AI tutor remains available after switching into a student workspace. - Workspace search queries classes, learners, courses and active lesson titles/body text, tasks, fee invoices, audience-visible announcement titles/bodies, and scoped attendance class/date records. Invoice results include only the current learner's invoices or invoices for a guardian's actively linked learners. Attendance search is limited to the 30 newest visible sessions and exact ISO dates; general content matching remains bounded case-insensitive substring search rather than full-text indexing.
- The AI tutor and teacher-assistant API/UI use a configurable provider abstraction, shared quotas, and usage metering, but no live provider credentials/model are configured. OpenAPI defines their bounded requests, usage counters, and draft/answer responses. Tutor lesson context is restricted to the learner's active enrollment or a teacher's created/assigned course scope; the regression confirms a course manager cannot forward another teacher's private lesson to the provider. The teacher assistant creates editable, unsaved lesson-plan, outline, objective, MCQ, exercise, homework, revision, and rubric drafts that require teacher review; it does not publish them. Prompt/context and generated-output redaction covers common emails, Indian mobile numbers, explicit international phone numbers, PAN-like identifiers, 12-digit identity-like strings, and labeled passport/voter-ID values, including lesson titles; it is not a full sensitive-data detector. Lesson context and direct learner/teacher override attempts are covered with fake-provider prompt-boundary fixtures, but no live-model prompt-injection evaluation has been run and prompt wording alone cannot guarantee resistance. Review provider retention terms before enabling real traffic. Content-grounded teacher generation, embeddings, voice, advanced multimodal features, and live-provider adversarial evaluation remain unimplemented.

- Announcements can publish immediately or be scheduled in the workspace timezone. Scheduled items remain manager-only until due; active audience members at publish time receive in-app notifications. - Workspace switching is available for active memberships. Dashboard summaries, tasks, class rosters, student attendance, attendance rates, academic reports, and tenant-scoped top-bar search load per selected organization.
- Workspace owners, admins, and educators can define and assign archived/recoverable custom permission profiles to active admin, educator, teacher, student, and guardian memberships. Owners cannot be assigned a custom profile. Profiles retain their base-role data scope and only narrow configured capabilities; educator custom profiles use explicit permissions and never inherit the default educator wildcard. Archiving retains assignments and narrowed permissions until restore or unassign. General-purpose audit logs and arbitrary capability grants are not implemented. Self-service password recovery remains implemented. Role changes use the existing audit log store; a workspace-scoped audit explorer is not implemented. Paid subscription decisions retain their own platform audit log.
- Live sessions use external HTTPS meeting and recording links. The app does not host media or sync calendars; join requests are logged but verified participant events need provider webhooks. Attendance can be marked by staff and saved into the existing attendance ledger.
